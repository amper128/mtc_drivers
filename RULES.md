# MTC binaRE — КОДЕКС: категорические правила

## ПРАВИЛО (категорическое): ЗАПРЕТ вызовов по сырому адресу

**ЗАПРЕЩЕНО** в реконструированном C-коде оставлять вызовы вида:

    return ((int (*)(int, int, int))(uintptr_t)0xFEF017C4)(nMHz, -0x110064, 0);

Это **вызов конкретной функции** (адрес 0xFEF017C4 = реальная функция), а НЕ "вызов по адресу".
Такой код обязан быть:

1. **Полностью дизассемблирован и декомпилирован** — тело вызываемой функции дописать.
2. **В IDB (`mtc_kernel.i64`) СНАЧАЛА** — декомпилировать/именовать функцию в IDB,
   чтобы зафиксировать и не потерять её структуру (функции, аргументы, тип).
3. **Заменён на именованный вызов** реальной функции:

    return ddr_change_freq_sram(nMHz);   // имя — из IDB/decompiled

### Допустимо (НЕ под запрет):
- Чтение/запись **аппаратного регистра** по адресу: `*(volatile uint32_t*)0xFED04048`
  (это memory-access, не вызов функции).
- `extern`-объявление + именованный вызов.

### Недопустимо (под запрет):
- `((type (*)(args))(uintptr_t)ADDR)(...)` — каст сырого адреса в function-pointer + вызов.
- `ldr Rn, =ADDR; blx Rn`, где ADDR = функция, без именованного прототипа.

### Процедура при встрече такого кода:
1. Взять адрес (напр. 0xFEF017C4).
2. IDB → decompile по адресу → установить ИМЯ + сигнатуру + тело функции.
3. Сохранить в IDB (функция именована, структура зафиксирована) + decompiled_*.c в src_all/.
4. В C — именованный вызов этой функции (не сырой адрес).

### Примечание:
В текущем IDB (mtc_kernel.i64) загружен только core-образ 0xC0400000–0xC0BE2030;
SRAM-регион 0xFEFxxxxx в IDB отсутствует → SRAM-функции (ddr_*_sram, ddr_get_pll_freq,
ddr_set_pll) идентифицируются по cross-ref из наших исходников ddr.c + decompiled,
вызов — по ИМЕНИ (ddr_change_freq_sram и т.д.). При необходимости SRAM-регион загрузить в IDB отдельно.

> Источник: user-директива (DDR-thunk review). Применяется ко ВСЕМ блокам реконструкции.
Пример применения: ddr_change_freq raw-addr 0xFEF017C4 → named ddr_change_freq_sram(nMHz) (patch 0051).
